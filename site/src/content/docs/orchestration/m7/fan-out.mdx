## Intuition

When work splits into independent pieces (pages, scenes, files), run them in parallel and merge:

- **Fan-out**: a conditional edge returns a list of `Send("worker", payload)`: one branch per item, decided at run time.
- **Fan-in**: workers write to a key with a reducer (`operator.add`), and the next node sees all results.
- **Limit**: pass `config={"max_concurrency": n}` so 100 items don't become 100 simultaneous model calls.
- **Partial failure**: catch per item, record the error, and keep going. Merge decides what "complete" means.

The media fan-out graph (a [worked example](/ai-native-course/orchestration/m7/media-fanout/)) runs 12 calls with a limit of 3 and measures a peak of exactly 3 in flight.

## C++/Rust notes
- Bounded fan-out ≈ a thread pool or a `tokio::sync::Semaphore` around spawned tasks; fan-in ≈ `join_all` collecting `Result`s rather than short-circuiting on the first error.
