## Intuition

A router sends each request down the right branch. Use the cheapest thing that works, in layers:

1. **Rules** (regex, keywords) for the obvious cases: free, instant, testable.
2. **A small model** as a classifier for the rest.
3. **A default** branch when neither is confident. Never drop a request.

**Model tiers** are the same idea for cost: short, simple prompts go to a small model, long or tool-heavy ones to a large one. **Fallbacks** catch provider errors: try the primary, on `ProviderError` try the backup, and record which one answered (your evals need to know).

The regex is `crash\w*`, not `crash`: an early version missed "crashes" and the test caught it. Rules need tests as much as models do.
