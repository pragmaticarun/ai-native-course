A plan that says "roll out agents to all teams in Q3" has no way to fail, so it has no way to succeed either. The template below (the course's) forces each stage to say what it watches, what must not get worse, and how you'll know it's done.

## Template

Each stage has:

- a **target level** and a name;
- an **owner** (a person, not a team);
- **metrics** with a **baseline** and a **target**;
- at least one **guardrail** metric: an instability or flow metric that must not get worse;
- an **exit criterion** you can check;
- an end date; the whole plan fits in 90 days.

`plan90.py` checks those rules and refuses vanity metrics (lines of code, % of code written by AI, prompt counts, accepted suggestions, PRs merged).

## Tips

- One level per stage. Ex 12.1 makes you critique a plan that doesn't.
- Stage 3 can be "stay here": consolidation is a legitimate outcome.
- Pick baselines from data you already have (M11's DORA metrics); if you have none, the first stage is "measure".

## C++/Rust notes
- Good systems-team guardrails: sanitizer findings per week, fuzz crashes, build time. Agents can make all three worse while lead time improves.
