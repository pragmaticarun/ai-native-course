The feature: in the Field Notes app (M10's Android fixture), add a "share clip" button to the clip detail screen.

## 1. Android Studio Agent Mode

Studio's agent works inside the IDE with its own tools: it reads AGENTS.md files (current directory and parents), edits code, builds, and can use device tools (deploy, screenshots, Logcat) with your permission. MCP servers extend it.

Workflow: describe the task, approve the plan, review each change as it's proposed, then let it deploy to an emulator and screenshot the result. You watch every step; the agent sees what you'd see.

## 2. Claude Code or Codex with the Android CLI plugin

Install the plugin (adds the `android-cli` skill), or run `android init` and `android skills add` (see [M10's Android example](/ai-native-course/ai-native/m10/android-repo/)). The skill teaches the agent the Android CLI, whose commands include:

| Command | Use |
|---|---|
| `android emulator create/start/stop` | manage virtual devices |
| `android run` | build, install and launch the app |
| `android layout` | dump the on-screen UI hierarchy as JSON |
| `android screen capture` | screenshot |
| `android studio …` | ask a running Studio for analysis (find usages, render a Compose preview) |

The agent edits code, runs `./gradlew :app:testDebugUnitTest`, then `android run` and `android layout` to check the button exists and has the right label.

## 3. Headless in CI

A job on a runner with the SDK and an emulator (set up with your CI's Android tooling, not shown):

1. The agent implements the change against the AGENTS.md verify tasks (unit tests, lint, screenshot tests).
2. A deterministic oracle, not the agent, starts the emulator, runs the app and saves `android layout` JSON.
3. A test asserts on the JSON (e.g. a node with text "Share" inside the clip detail screen).

The layout JSON is a better oracle than a screenshot for "is it there and labelled right", and cheaper than an instrumented test.

## Journeys

Journeys (Studio, also callable from the Android CLI) are end-to-end tests written in natural language and executed by an agent on a device. They're a useful layer for agent-written UI tests, with the usual caveat: an agent judging an agent's work needs human spot checks.

## Which one when

| | Studio Agent Mode | CLI agent + plugin | Headless CI |
|---|---|---|---|
| You watch | every step | as much as you like | only the PR |
| Device access | Studio's device tools | Android CLI | emulator on the runner |
| Best for | UI work you'll iterate on | scripted, repeatable tasks | well-specified changes with an oracle |

## C++/Rust notes
- For NDK code, keep native logic testable on the host (CMake/Cargo host builds) so the agent's loop doesn't need an emulator; use `android run` + Logcat only for JNI and ABI checks.
