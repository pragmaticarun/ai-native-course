## The kit

`World` is the outside world in SQLite: per-service config, a change log keyed by idempotency key, an outbox, and an attempts table that lets the evals see retries. `MockTriageModel` classifies from the report and proposes a change from the logs. `p4_legacy.py` is **v0 of your workflow, already deployed**: v1 must replay its histories.

## M1–M2 · Pipeline and activities

The workflow only orchestrates. Everything that touches the world, including the model, is an activity, so its result is recorded in the history and a replay doesn't call the model again (one eval counts the model calls). The log tool times out on its first call per incident; a `RetryPolicy` handles it.

Idempotency keys come from the incident, not the attempt: `INC-101:apply`. A retried `apply_fix` finds its own earlier change and returns the values it recorded the first time.

## M3 · The human gate

The decision is a signal (`decide(Decision)`); a query (`state`) shows what's pending. Waiting is `workflow.wait_condition(..., timeout=...)`: a durable timer in the history, not a sleeping process. One day without an answer sends a reminder; three days expires the request with nothing changed. An approver can edit the change; if the edited change doesn't make the health check pass, the workflow rolls back to the recorded previous values.

## M4 · Kill -9 and versioning

Worker A runs in its own process, applies the fix, then hangs. The eval kills it with `SIGKILL`. The heartbeat timeout (2 s) notices, the activity is retried on worker B, and B finds the change already recorded under its key: **attempts A, B; one change**.

v1 adds "notify the owner on close". Runs started on v0 may still be waiting for approval when v1 ships, so the new step sits behind `workflow.patched("notify-owner-on-close")`. The eval records v0 histories (approved and rejected) and replays them against your v1 with Temporal's `Replayer`. Without the patch, replay fails with a non-determinism error (that's why the starter fails it).

## C++/Rust notes

- A workflow is a deterministic state machine whose input log is the history; replay is "re-run the reducer over the event log". Anything non-deterministic (clock, random, I/O) must be an activity or come from the SDK (`workflow.now()`).
- Temporal's Python and TypeScript SDKs sit on a shared Rust core (`sdk-core`); the warnings you see in test output come from it. There's no official C++ SDK.
- Idempotency keys are the distributed version of "make the operation safe to retry": think `INSERT ... ON CONFLICT DO NOTHING`, not a mutex.
