## Intuition

Tools are an API whose caller is a stochastic planner that reads your docstrings. Design rules:

| Rule | Why | In the explorer |
|---|---|---|
| **Right granularity**: one tool per user-meaningful step | too fine = many steps and tokens; too coarse = no control | `grep` instead of "read every file" |
| **Read vs write separation** | you can auto-approve reads, gate writes | all three tools are read-only |
| **Idempotent where possible** | the model will retry | reading twice is harmless |
| **Bounded output** | protects the context window | `read_file` truncates, `grep` caps hits at 50 |
| **Errors for the model** | it can only fix what it can read | `"error: 'x' is outside the sandbox"`, `"no tool named 'y'; available: [...]"` |
| **Enforce limits in code** | prompts are suggestions | path resolution + `is_relative_to(root)` |

## Smallest example

```python
def read_file(path: str, max_chars: int = 2000) -> str:
    """Read a text file (read-only, truncated)."""   # the model reads this
    p = (root / path).resolve()
    if not p.is_relative_to(root):
        raise PermissionError(f"{path!r} is outside the sandbox")  # becomes an observation
    return p.read_text(errors="replace")[:max_chars]
```
