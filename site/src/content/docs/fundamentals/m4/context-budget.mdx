## Intuition

The context window is RAM, not disk. Everything the model sees on a call competes for it: instructions, tool specs, retrieved data, history. Bigger windows don't remove the problem. Long prompts cost more, run slower, and bury the important parts. So decide **priorities** up front:

1. **Instructions and tool specs:** never dropped. If they alone don't fit, that's a design bug, so fail loudly.
2. **Retrieved data:** the most relevant first, each document capped, and the total capped at a share of the budget.
3. **History:** newest first, so the oldest turns go first.

Truncate *visibly* (`…[truncated]`) so the model knows it saw a partial result and can ask for more.

## C++/Rust notes
- The window ≈ a fixed-size cache with an eviction policy you choose (here, priority classes plus LRU on history).
- `build_context` raising on oversized fixed sections ≈ a `static_assert` on a buffer size: fail early, not with silent truncation.
