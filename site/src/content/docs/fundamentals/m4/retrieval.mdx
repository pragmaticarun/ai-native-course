## Intuition

Retrieval quality sets the ceiling on answer quality. The pipeline:

1. **Chunk** with overlap, and keep `path:start-end` on every chunk so answers can **cite**.
2. **Lexical search (BM25)** is unbeatable for identifiers (`parse_config`), error codes, and flags. Split `camelCase`/`snake_case`.
3. **Dense search** catches paraphrases. Here a hashed character-trigram vector *stands in* for an embedding model so the example runs offline.
4. **Hybrid:** fuse the two rankings with **reciprocal rank fusion** (sum of `1/(k+rank)`), which needs no score calibration.
5. **Rerank** the top few with something more expensive (a cross-encoder or model in production; simple bonuses here).

<Aside type="note">
The trigram "embedding" captures spelling similarity, not meaning. It's there to show the plumbing (vectors, cosine, fusion), not to claim semantic recall.
</Aside>

## C++/Rust notes
- BM25 over an inverted index ≈ what `ripgrep` + ranking would be; `tantivy` (Rust) and Lucene implement it properly.
- RRF ≈ merging k sorted streams by rank, with no shared score scale needed.
