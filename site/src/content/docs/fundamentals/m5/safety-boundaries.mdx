## Intuition

Assume the model will eventually call the worst tool with the worst arguments, through a bug, a bad plan, or a prompt injection. Design so that this is survivable:

- **Least privilege:** each task gets only the tools it needs (`for_task({"read"})`).
- **Dry run:** write tools describe what they *would* do; show that plan, then run for real.
- **Sandboxes:** confine paths to a root (and in production, processes to a container or VM with no network by default).

## C++/Rust notes
- ≈ `seccomp`/`pledge`/`unveil`: drop privileges you don't need before running untrusted logic.
- Dry run ≈ `make -n` or `terraform plan`: print the effects before applying them.
