## Intuition

It's the [L2.3](/ai-native-course/fundamentals/m2/structured-output/) loop again (ask for JSON, validate, repair once), written in Kotlin so it can live in an Android app. All agent logic sits in **`commonMain`** and depends on one small interface, `OnDeviceLlm`. Real backends plug in from `androidMain`; tests use fakes.

- **Galaxy A73 path:** LiteRT-LM on CPU (Gemma 3 1B). In this repo it's represented by `ScriptedLiteRtLm`, a fake.
- **Documented Gemini Nano path:** ML Kit Prompt API (`genai-prompt`) with its ~4k-token input guidance, a `countTokens` check, and `BUSY` handled with exponential backoff. The A73 isn't on Google's supported-device list, so this path runs only through `RecordedGeminiNano`, which replays responses and error codes.

<Aside type="caution" title="What was actually run">
**Tested:** `commonMain` + `commonTest` on the **JVM target** (Kotlin 2.4.21, Temurin 21, Gradle 9.9.1), locally and in CI (`./gradlew :shared:jvmTest`, 6 tests in this file).
**Not built or run yet:** the real LiteRT-LM and ML Kit backends for this example, and anything on the Galaxy A73. (Since 14 Nov 2026 `kmp/shared` also builds as an Android library in CI and runs these tests as Android host tests; [P6](/ai-native-course/projects/p6/) has the LiteRT-LM backend.) The error-code names mirror ML Kit's documented codes, but `ErrorCode` is our own type, not the ML Kit API.
</Aside>

## Try it
1. Add a `PER_APP_BATTERY_USE_QUOTA_EXCEEDED` test: it should fail fast, not retry.
2. Make `maxRepairs` 2 and write a test where the second repair succeeds.
3. Sketch the `androidMain` LiteRT-LM implementation of `OnDeviceLlm` (it will be built and run on the A73 in M13).

## C++/Rust notes
- `OnDeviceLlm` ≈ a trait object (`Box<dyn OnDeviceLlm>`): the platform-specific backend is injected; `commonMain` ≈ a `no_std`-style core crate.
- `sealed interface LlmResult` ≈ a Rust `enum` with data; `when` is an exhaustive `match`.
