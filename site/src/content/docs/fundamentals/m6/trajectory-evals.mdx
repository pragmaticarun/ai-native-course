## Intuition

Two agents give the same right answer. One grepped once; the other listed every directory, read 40 files, and tried to open `../.env`. Final-answer evals score them the same. **Trajectory graders** look at *how* it got there:

- `calls_first("grep")`: the efficient first move;
- `at_most_calls(n)`: a step/cost budget as an assertion;
- `never_calls("list_dir")` / forbidden tools: safety and efficiency;
- `in_order("grep", "read_file")`: required ordering as a subsequence.

In the AI SDK the trajectory is just `result.steps.flatMap(s => s.toolCalls)`, and a **token budget** can be a custom `stopWhen` condition:

## Try it
1. Add a grader that fails if the same tool is called with the same arguments twice in a row (M3's loop detector, as an eval).
2. Should trajectory checks be strict (exact sequence) or loose (properties)? Write one of each and decide which breaks first when the model improves.

## C++/Rust notes
- ≈ asserting on a mock's call log (gmock `EXPECT_CALL(...).Times(1)`, `mockall` expectations), not just the return value.
