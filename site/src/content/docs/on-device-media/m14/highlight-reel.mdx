The agent turns a 10.5 s match clip into a 3.2 s reel of the two most exciting shots, at −16 LUFS, and proves it did.

## Python

<Snippet path="examples/python/m14/highlight_reel.py" />

Run it: `cd examples/python && uv run --project ../../python python -m m14.highlight_reel`. The trace:

```text
probe: 10.52s 320x240 @ 25.0fps
scene_cuts: [2.0, 3.52, 6.04, 8.04] -> 5 shots
transcribe: 4 segments
score: [0.0, 0.0, 1.0, 0.0, 1.0]
plan: [(2, 3.72, 5.32), (4, 8.24, 9.84)]
verify: ok
```

Design points:

- **The plan is data.** `EdlEntry(shot, src_in, src_out, score, reason)` can be shown to a human, stored, and diffed. Entries are frame-snapped and start 0.2 s after the cut so a late detector never leaks the previous shot.
- **Greedy under a budget, then story order.** Pick by score until the duration budget is spent, then sort by time.
- **Verify against the plan, not the agent.** Duration ±0.1 s, one video and one audio stream, loudness ±1 LU, and cut points at the cumulative entry lengths ±1 frame. A wrong render (one entry, −23 LUFS) fails on duration and loudness in the tests.

## C++/Rust notes
- The verify step is a good first Rust component: a CLI that takes the EDL JSON and the output file, and exits non-zero with reasons. The M9 Rust `rmcp` media-probe server already has `probe` and `loudness`.

## Kotlin notes
- On Android, a Media3 Transformer `Composition` of `EditedMediaItem`s with clipping configurations is the counterpart of the concat graph; run the export in a foreground service and the scoring model while the app is visible (*untested*).
