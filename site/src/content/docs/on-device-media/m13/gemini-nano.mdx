## What it is

ML Kit GenAI runs Gemini Nano on the device through **AICore**, an Android system service. There are **task APIs** (summarization, proofreading, rewriting, image description, speech recognition) and **direct model access** through the Prompt API (`com.google.mlkit:genai-prompt`, latest `1.0.0-beta5`; the docs show beta4).

Documented limits to design around:

- input under about **4,000 tokens**; API 26+;
- inference only while the app is the **top foreground app** (`BACKGROUND_USE_BLOCKED` otherwise);
- per-app quotas (`BUSY`, `PER_APP_BATTERY_USE_QUOTA_EXCEEDED`);
- not supported on unlocked bootloaders;
- outputs differ across Nano versions (`getBaseModelName()`), so evaluate prompts per version;
- model tiers per Firebase docs: `STABLE` (Nano 3 `nano-v3` / `nano-v2`), `PREVIEW` (Nano 4 Full, based on Gemma 4 E4B), `PREVIEW_FAST` (Nano 4 Fast, based on Gemma 4 E2B).

## The A73's answers (from the docs)

| Feature | Expected status on the A73 |
|---|---|
| Prompt API, summarization, proofreading, rewriting, image description | unsupported (not on the device list) |
| `genai-agent` `AgentRunner` | unsupported (needs a listed device in the AICore Developer Preview) |
| speech recognition, **Basic** mode | supported (API 31+; the A73 launched on Android 12) |
| speech recognition, Advanced mode | unsupported |

## Availability as a state machine

Feature status (`UNAVAILABLE`, `DOWNLOADABLE`, `DOWNLOADING`, `AVAILABLE`) and runtime errors map to honest UI states: "not on this phone, using the fallback", "download the model?", progress that never goes backwards, "open the app to continue", bounded retries on `BUSY`, then fallback.

## Kotlin notes
- Expose availability as a `StateFlow<UiState>` from a `ViewModel`; collect download progress as a `Flow` and fold it with `max` so the bar never moves backwards.
- Gate calls on `Lifecycle.State.RESUMED`: the foreground-only rule makes background work a design error, not a retry.
